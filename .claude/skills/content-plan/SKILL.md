# 콘텐츠 기획 (Notion)

인자로 주제나 slug를 받는다. 예: `/content-plan 노션 DB 입문자가 하는 실수`
인자가 없으면 DB에서 `아이디어`·`조사중` 상태의 행을 보여주고 선택을 요청한다.

**이 스킬은 Figma를 건드리지 않는다.** 출력물은 Notion 페이지 하나다.

## 시작 전 반드시 읽는다
1. `AGENTS.md` — 공용 절대 규칙
2. `design/content-plan.md` — **기획 문서 규격 (DB 스키마 · 본문 스켈레톤 · 파싱 계약)**
3. `design/formats.md` — 포맷 규격 · 카테고리별 강조색 · 카피 톤
4. `design/brand.md` — Notion 보이스
5. `content/notion.json` — DB ID 등 연결 정보

---

## 0단계 — 연결 확인

**노출된 Notion MCP 도구 이름을 먼저 확인한다.** 등록된 서버에 따라 다르다.

| 등록된 서버 | 도구 이름 |
|---|---|
| 로컬 `scripts/notion-mcp.mjs` (기본) | `API-post-search` · `API-retrieve-page-markdown` · `API-query-data-source` … |
| 호스팅 `mcp.notion.com` | `notion-search` · `notion-fetch` · `notion-create-pages` … |

도구가 아예 없으면 **여기서 멈추고** 사용자에게 설정을 요청한다 (README 4.3).
Notion 없이 기획 문서를 로컬에 만들지 않는다. 그렇게 하면 산출물이 두 군데로 갈라진다.

호출이 401/403으로 실패하면 원인을 가려서 안내한다. 같은 호출을 반복하지 않는다.

```bash
node scripts/notion-mcp.mjs --check
```

- **토큰이 거부됨** → `.env`의 `NOTION_TOKEN`이 잘못됐다
- **토큰은 통과, 페이지가 안 보임** → **권한** 문제다. 내부 통합은 명시적으로 공유한
  페이지만 본다. 상위 페이지에서 ⋯ → 연결(Connections) → 통합 추가를 요청한다

`content/notion.json`의 `database.id`가 `null`이면 **DB가 아직 없다.**
사용자에게 DB를 만들 상위 페이지를 물어보고(위에서 통합에 공유한 그 페이지다),
`design/content-plan.md` 1항의 스키마 그대로 «콘텐츠 기획» DB를 만든 뒤
`id` · `dataSourceId` · `url` · `workspace` · `parentPageId`를 `content/notion.json`에 기록한다.

## 1단계 — 중복·맥락 점검

DB의 기존 행을 조회한다.

- 같은 `slug` 또는 겹치는 `태그`의 게시물이 이미 있는가 → 있으면 **무엇이 다른지** 정리해 보고한다
- 최근 발행된 게시물의 강조색·포맷 → 연달아 같은 색·같은 포맷이면 기획 단계에서 짚어준다
- 기존 게시물에서 이어받을 맥락(시리즈, 후속편)이 있는가

겹치는 주제가 있으면 **여기서 사용자에게 확인**한다. 조사부터 하고 나서 버리는 것은 낭비다.

`content/briefs/<slug>.md`가 있으면 그 내용을 출발점으로 삼는다. 없어도 된다 —
브리프는 선택 사항이고, 기획의 정본은 Notion 페이지다.

---

## 2단계 — 조사

`design/content-plan.md` 5항의 조사 규칙을 따른다. **출처 없는 사실은 카드에 넣지 않는다.**

| 무엇을 | 어떻게 |
|---|---|
| 주제 관련 사실·통계·사례 | `exa` 웹 검색 / `WebSearch` |
| 노션 기능의 정확한 동작 | **노션 공식 도움말 문서**를 직접 확인한다. 기억으로 쓰지 않는다 |
| 조판·구성 레퍼런스 | `@notionhq` · `@notionhq_kr` 등 노션 공식 SNS 게시물 |
| 주제 중복·톤 일관성 | 1단계에서 조회한 기존 DB 행 |
| 이미지 소스 | 카드별로 필요한 이미지와 그 출처(직접 스크린샷/촬영/무료 라이선스) |

레퍼런스 관찰은 **문장을 가져오는 것이 아니다.** 표지에 몇 자를 썼는지, 카드당 몇 줄인지,
이미지를 어디에 뒀는지 같은 **구성과 분량**을 적는다. 남의 카피를 그대로 옮기지 않는다.

`firecrawl` MCP는 연결 실패 상태일 수 있다. 실패하면 `exa`로 대체하고, 대체했다는 사실을 보고한다.

## 3단계 — 기획 문서 작성

DB에 행을 만들고(또는 기존 행을 열고) 본문을 `design/content-plan.md` 2항 스켈레톤 그대로 채운다.
**제목 문자열과 순서를 바꾸지 않는다.** 디자인 단계가 이 구조에 기대어 읽는다.

본문은 **블록 JSON이 아니라 마크다운으로** 쓴다 (`API-update-page-markdown`).
스켈레톤이 마크다운 헤딩 구조라 그대로 들어가고, 블록을 쪼개는 것보다 훨씬 싸다.
기존 페이지를 고칠 때는 `replace_content`가 본문 전체를 덮어쓰므로 **먼저 읽고**
(`API-retrieve-page-markdown`) 합친 결과를 쓴다. 사람이 적어둔 내용을 날리지 않는다.

DB 속성을 먼저 정한다:
- `slug` — `^[a-z0-9-]+$`, 기존 행과 중복 금지. repo·Figma·exports 전부 이 값을 쓴다
- `포맷` · `카드 수` — `design/formats.md`의 권장 장수(카드뉴스 5~8, 최대 10) 안에서
- `강조색` — `design/formats.md`의 카테고리 표에서 주제에 맞는 **1개**
- `테마` — `light` 또는 `dark` 하나
- `상태` — 조사 시작 시 `조사중`, 작성을 마치면 `기획완료`

본문 작성 시:
- **`## 3. 카드 구성`의 영문 키는 그대로 Figma에 들어간다.** 오타가 곧 디자인 오류다.
  컴포넌트별 키 목록은 `design/content-plan.md` 3항 표에 있다.
- `theme` · 뱃지/콜아웃 `color` · 진행표시 숫자는 **쓰지 않는다.** 디자인 단계가 DB 속성에서 정한다.
- `showImage`를 여기서 확정한다. 켠 카드는 텍스트를 더 줄인다(표지 2줄·본문 4줄·인용 3줄).
- `## 5. 이미지 계획` 표를 채우고, 파일이 아직 없으면 상태를 `필요`로 둔다.
- `## 6. 디자인 결과`는 **비워둔다.** 디자인 단계가 채운다.

## 4단계 — 규격 검증

작성한 카피를 `design/formats.md` 기준으로 직접 세어 확인한다. "대충 맞겠지"로 넘기지 않는다.

- [ ] 표지 `title` 20자 이내 (`showImage: true`면 2줄 안에 떨어지는가)
- [ ] 본문 `title` 15자 이내
- [ ] `body` 카드당 150자 이내, 2~4문장, 한 카드 = 한 메시지
- [ ] 카드뉴스 구성이 `CN/Cover` 1 → 본문 n → `CN/CTA` 1
- [ ] 마지막 카드에 행동 유도가 **하나만**
- [ ] 강조색 1개 · 테마 1개로 통일
- [ ] 낚시성 표현·과장·느낌표 남발이 없는가 (노션 보이스)
- [ ] AI 보고서체나 딱딱한 번역투가 아닌, 학우에게 직접 말하듯 자연스럽고 따뜻한 사람다운 어조인가
- [ ] 캡션(피드 본문)이 단순 요약 복사가 아닌, 실제 인스타 피드에 맞게 첫 인사·공감·알찬 정리·친근한 CTA를 갖추었는가
- [ ] 전문 용어가 첫 등장에서 한 줄로 풀렸는가
- [ ] 모든 사실 주장에 출처 링크가 있는가
- [ ] 이미지 계획의 모든 항목에 출처가 적혔는가

문제가 있으면 **문서를 고친 뒤** 다음으로 간다. 문제를 안고 넘기지 않는다.

## 5단계 — 보고

상태를 `기획완료`로 올리고 사용자에게 보고한다.

- Notion 페이지 링크
- `slug` · 포맷 · 강조색 · 테마 · 카드 수
- 카드별 제목 한 줄 요약 (전체 흐름이 보이게)
- 사용한 출처 목록
- **사람이 채워야 할 것**: 아직 없는 이미지 파일, 확인이 필요한 사실, 정하지 못한 선택지

그리고 다음 단계를 안내한다: `/instagram-post <slug>`

`content/notion.json`의 `lastUpdated`를 갱신한다.

---

## 하지 않는 것

- Notion 인증 없이 로컬에 기획 문서 만들기 (산출물이 갈라진다)
- Figma에 쓰기 — 이 스킬은 Figma를 열지 않는다
- 출처 없는 사실을 카드에 넣기
- 레퍼런스 게시물의 카피를 그대로 옮기기
- `## 6. 디자인 결과` 채우기
- 스켈레톤의 섹션 제목·순서 바꾸기
