# 콘텐츠 기획 문서 규격 (Notion)

게시물의 **기획·조사·이미지 계획**은 Notion에 산다. 저장소에는 디자인 직전에 확정된
카피만 `content/posts/<slug>.md`로 내려받아 남긴다.

```
Notion  «콘텐츠 기획» DB      조사 · 기획 · 이미지 계획 · 검토   (사람과 에이전트가 함께 고침)
  │  /content-plan 이 만들고 채운다
  ▼
repo    content/posts/<slug>.md   확정 카피 스냅샷            (git 이력 · 오프라인 검토)
  │  /instagram-post 이 내려받고 승인받는다
  ▼
Figma   02_Workspace 섹션          조립된 카드
  │
  ▼
Notion  같은 페이지 «6. 디자인 결과»  노드 ID · 내보낸 파일 (되돌려 기록)
```

연결 정보(DB ID, 데이터소스 ID, 상위 페이지 ID)는 `content/notion.json`에 기록한다.
`design/figma-file.json`이 Figma 쪽에서 하는 역할과 같다. MCP 설치는 README 4.3.

**본문은 마크다운으로 읽고 쓴다.** 아래 스켈레톤이 마크다운 헤딩 구조인 이유가 이것이다 —
원격 서버의 `notion-fetch` / `notion-update-page` (또는 로컬의 `API-retrieve-page-markdown` / `API-update-page-markdown`)를
통해 페이지 전체를 다룰 수 있고, 블록 JSON을 쪼개는 것보다 토큰이 훨씬 적게 든다.
수정할 때는 **먼저 읽고 합쳐서** 쓴다. 통째로 덮어쓰거나 매칭되지 않는 부분 치환으로 인해 사람이 적어둔 내용이 날아가지 않도록 주의한다.

## 1. 데이터베이스 «콘텐츠 기획»

게시물 하나 = 행 하나 = 페이지 하나.

| 속성 | 타입 | 값 | 비고 |
|---|---|---|---|
| `제목` | title | 내부용 제목 | 표지 제목과 같을 필요 없다 |
| `slug` | rich_text | `^[a-z0-9-]+$` | **repo · Figma · exports 공용 키.** 중복 금지 |
| `포맷` | select | `카드뉴스` \| `단일 포스트` \| `스토리` | `design/formats.md` |
| `강조색` | select | `blue` `purple` `orange` `red` `green` `gray` | 게시물당 1개 |
| `테마` | select | `light` \| `dark` | 게시물 안에서 통일 |
| `카드 수` | number | 카드뉴스 5~10 | 다른 포맷은 1 |
| `상태` | select | 아래 흐름 참조 | |
| `발행 예정일` | date | | |
| `태그` | multi_select | 주제 분류 | 중복 주제 점검에 쓴다 |
| `Figma 섹션` | rich_text | `YYYY-MM-DD_<slug>` | 디자인 단계가 채운다 |
| `내보내기 경로` | rich_text | `exports/<slug>/` | 디자인 단계가 채운다 |

### 상태 흐름

```
아이디어 → 조사중 → 기획완료 → 카피승인 → 디자인중 → 발행준비 → 발행됨
                        │            │
        /content-plan 종료      사람이 카피를 승인한 시점
```

- **`/instagram-post`는 `기획완료` 이상에서만 시작한다.** 그 아래면 거부하고 기획을 먼저 하도록 안내한다.
- 상태를 올리는 주체: `조사중`·`기획완료`는 `/content-plan`, `디자인중`·`발행준비`는 `/instagram-post`,
  `카피승인`과 `발행됨`은 **사람만** 올린다.

## 2. 페이지 본문 스켈레톤

제목 문자열과 순서를 **바꾸지 않는다.** 디자인 단계가 이 구조에 기대어 읽는다.
빈 섹션도 지우지 말고 헤딩만 남긴다.

## 3. 카드 필드 규칙 — **이것이 파싱 계약이다**

`## 3. 카드 구성` 안의 각 `### NN — <컴포넌트>` 블록에서:

- **영문 소문자로 시작하는 키 = Figma 컴포넌트 프로퍼티.** 이름과 값이 그대로 인스턴스에 들어간다.
- **한글 키 = 사람용 메모.** Figma에 들어가지 않는다.
- 없는 값은 `—` 로 둔다. 줄 자체를 지우지 않는다.

| 컴포넌트 | 영문 키 (Figma로 들어감) |
|---|---|
| `CN/Cover` | `title` `subtitle` `showBadge` `showImage` |
| `CN/Body` | `title` `body` `showImage` `showCallout` `showCaption` `caption` |
| `CN/Quote` | `quote` `source` `showImage` |
| `CN/CTA` | `headline` `sub` `showImage` |
| `PT/Single` | `title` `body` `showImage` |
| `ST/Base` | `title` `body` `showImage` |

**중첩 인스턴스에 들어가는 값** (컴포넌트 프로퍼티가 아니라 노출된 인스턴스를 직접 고친다):

| 키 | 들어가는 곳 | 조건 |
|---|---|---|
| `badge` | `CN/Cover`의 `UI/Badge.text` | `showBadge: true`일 때만 |
| `badge` | `PT/Single`의 `UI/Badge.text` | 항상 (`PT/Single`에는 `showBadge` 축이 없다) |
| `callout.emoji` `callout.text` | `CN/Body`의 `UI/Callout` | `showCallout: true`일 때만 |

`caption`은 이미지 출처를 다는 칸이다. `CN/Body`에만 있고 `showImage: true`인 카드에서만 의미가 있다.
출처 문구는 «5. 이미지 계획»의 `출처`와 같은 내용을 짧게 줄여 쓴다. (2026-09-10 추가)

**기획 문서에 쓰지 않는 값** — 디자인 단계가 자동으로 정한다:

- `theme` — DB 속성 `테마`에서 가져와 전 카드에 똑같이 적용한다. 카드별로 다르게 쓰지 않는다.
- `UI/Badge.color`·`UI/Callout.color` — DB 속성 `강조색` 하나를 전 카드에 쓴다.
- `UI/ProgressDots`의 `current`/`total` — 카드 번호와 총 장수에서 계산한다.

## 4. 기획 단계가 지켜야 할 규격

`/content-plan`은 카피를 쓰는 순간 `design/formats.md`의 제약을 이미 만족시켜야 한다.
디자인 단계에서 글자 수를 줄이려고 되돌아오는 것이 가장 비싸다.

- 표지 `title` **20자 이내** · 본문 `title` 15자 이내 · `body` 카드당 **150자 이내, 2~4문장**
- `showImage: true`인 카드는 텍스트를 더 줄인다 — 표지 제목 2줄, 본문 4줄, 인용 3줄
- 카드뉴스는 `CN/Cover` 1장 → 본문 n장 → `CN/CTA` 1장. 마지막 카드에 행동 유도 **하나만**
- 한 게시물에 강조색 1개, 테마 1개
- **카피 톤 (사람다운 톤앤매너 · 캠퍼스 앰버서더 보이스)**:
  - AI 보고서체나 번역투·관료적 설명문("~기준으로 운영", "~자리가 생겼어요")을 지양한다.
  - 화자는 제3자 관찰자가 아니라 학우들에게 친근하게 다가가는 **한국항공대 공식 학생 앰버서더(Notion Campus Leader)**다.
  - 학우의 눈높이에서 학교생활 맥락(수강신청, 팀플, 과제, 동아리 등)을 구체적으로 짚고, "~도우려 해요", "~함께 만들어가요", "~찾아올게요"처럼 생생하고 능동적인 자연스러운 한국어 해요체를 쓴다.
  - 과장이나 느낌표 남발은 절제하되, 건조하지 않고 반갑고 따뜻한 온도를 유지한다.
- **캡션(피드 본문) 작성 원칙**:
  - 단순 카드 텍스트 복사나 불릿 나열이 아니라, 실제 인스타그램 피드에 맞게 **첫 인사 · 학우 공감대 · 이모지를 곁들인 알기 쉬운 정리 · 친근한 팔로우 유도(CTA)**가 갖춰진 완전한 포스팅 문장으로 작성한다.

## 5. 조사 규칙

- **모든 사실 주장에 출처 링크를 단다.** 출처 없는 문장은 카드에 넣지 않는다.
- 노션 기능을 다룰 때는 **공식 도움말 문서**로 확인한다. 기억으로 쓰지 않는다.
- 레퍼런스는 `@notionhq` · `@notionhq_kr` 등 **노션 공식 SNS**를 우선 본다.
  베낀 문장을 가져오는 것이 아니라 **구성·분량·조판 관찰**을 적는다.
- 기존 DB 행을 조회해 **주제 중복**과 톤 일관성을 점검하고, 겹치면 기획 단계에서 보고한다.
- 조사했지만 뺀 것은 «쓰지 않기로 한 것»에 이유와 함께 남긴다. 다음 기획에서 다시 파지 않기 위해서다.

## 6. 이미지 계획

`showImage`는 **기획 단계에서 정한다.** 디자인 단계에서 즉흥으로 켜지 않는다.
슬롯은 16:9(920×518)이고, 켜면 정사각형 1080px 중 518px을 먹는다(`design/formats.md`).

이미지 파일은 `content/images/<slug>/` 에 둔다. 기획 문서 «5. 이미지 계획» 표의 `파일명`이
그 폴더 안의 이름이다. 파일이 아직 없으면 상태를 `필요`로 두고, 디자인 단계는 슬롯을
회색 플레이스홀더로 남긴 채 조립한 뒤 **무엇이 비었는지 보고**한다.

출처는 셋 중 하나로 적는다: `직접 스크린샷` · `직접 촬영` · `<서비스명> 무료 라이선스 + 링크`.
출처가 불분명한 이미지는 계획에 넣지 않는다.
